### 改动 2：`src/api.js`（`getProduction`）
- **为什么**：后端 `aicontroller.show(String id)` 挂在 `@GetMapping("/show/{id}")` 上却**漏写 `@PathVariable`**。
  Spring MVC 只有见到该注解才绑定 URI 模板变量（官方文档明确：能省的只是注解里的名字），
  否则按普通请求参数解析 → 后端拿到的 `id` 为 `null` → 详情恒返回「暂无对应内容」。
- **改了什么**：`request(\`/ai/show/${id}\`, { params: { id } })`，id **同时**写进路径和查询串。
  后端补注解则走路径变量，不补则走查询参数，两种都成立。根治仍需后端加注解。

### 改动 3：`src/views/PaySuccess.vue`

## 启动报错定位（主人 14:12 报「后端又爆炸」）
- **现象**：`PlaceholderResolutionException: Could not resolve placeholder 'EMAIL' in value "${EMAIL}" <-- "${spring.mail.username}"`。
- **根因（环境问题，非代码）**：`application.yml` 有 6 个无默认值占位符，User/Machine/Process 三级均未设环境变量。
  `MailUtil` 用 `@Value("${spring.mail.username}")` 直接读该属性 → 解析失败即断言崩溃；
  `AliPayConfig` 走 `@ConfigurationProperties` 相对宽容，所以报错的第一个是 EMAIL。
- **实测结论**：补上 6 个占位值后 `mvn spring-boot:run` **一路启动成功** ——
  `Tomcat started on port 8080` + `amqp://guest@192.168.246.134:5672` + `Started AiRentPlatformApplication in 2.657 seconds`，零 ERROR。
  即**这 6 个变量是唯一硬阻断**。（MySQL/Redis 是懒连接，启动期不建连，首次查询才验证。）
- **顺带挖出宿主陷阱（重要）**：WorkBuddy 会给子进程注入 `SERVER__PORT=51083`（双下划线），
  Spring Boot 宽松绑定把它解析成 `server.port=51083`，而 51083 正被 WorkBuddy.exe 自己占用
  → **凡在 WorkBuddy 终端里启动，必报 `Port 51083 was already in use`**（与 8080 无关，极具误导性）。
  解法：启动前 `Remove-Item Env:SERVER__PORT`，或显式加 `--server.port=8080`。IDEA / 普通 cmd 里没有这个变量。
- 排查手法沉淀：PowerShell stdout 拿不回 → `Start-Process -RedirectStandardOutput <log>` 落盘再 Read；
  `Start-Process` + `Wait-Process -Timeout` + 按 StartTime 杀本次 java，可安全做「启动即验证」而不残留进程。

## 17:10 主人纠偏：`/user/aitask` 不该收 username，身份只认 Session（已实施）
- **主人原话**：「用户查询自己ai生成任务不需要传用户名啊，直接到session里面获取啊」——**判断正确**。
- **为什么原设计是错的**：接口语义就是「查我自己的」，客户端本就不该提供身份。上一版把 `username` 当入参再回比 Session
  「仅用于自证」，是冗余设计：多一个入参、多一条拒绝分支，还给外部留了「传别人名字→试探」的探针面。
  改成「身份零入参」后，越权从「被拒绝」升级为「**无从表达**」。
- **改动 4 处**：
  1. `usercontroller.myAitask(HttpSession session, String username)` → `myAitask(HttpSession session)`，删掉
