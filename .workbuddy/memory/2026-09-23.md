## 18:50 修「套餐一上架，算力和金额被清零」（主人报告，已修复并端到端验证）
- **现象**：后台管理页新增套餐正常，但**一点"上架"**，该套餐的 `money`（算力）与 `rmb`（金额）就变成 0。

  （默认值 0，永远不为 null），MyBatis-Plus 默认的 `FieldStrategy.NOT_NULL` **只跳过 null、不跳过 0**
  → 生成 `UPDATE token_spu SET money=0, rmb=0, status=? WHERE id=?`。
  旁证：`name` 是 `String`，未设置时为 null 被策略跳过，所以**只有算力和金额被清、名字完好** —— 与现象精确吻合。
  `application.yml` 未覆盖 `mybatis-plus.global-config`，确认走的就是默认策略。
- **修复（最小改动，主人只说修上架这一处）**：`admincontroller.java` 两处 ——
  ① 补 `import com.baomidou.mybatisplus.core.conditions.update.UpdateWrapper;`；
  ② `upspu` 改为 `UpdateWrapper<TokenSpu> uw; uw.eq("id",id).set("status",status); spuMapper.update(null,uw);`
  即**只更新 status 一列**，其余列一概不碰。编译 `mvn -DskipTests compile` → BUILD SUCCESS、零 ERROR。
- **未修的同类隐患（已报告主人，等其发话）**：`reviseSpu`（`POST /admin/revisespu`，"保存套餐信息"）
