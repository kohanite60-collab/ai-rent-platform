## 晚间：排查「前端登录不上去」

### 环境侧结论
- 前端 dev server 在 5173 正常（HTTP 200）；**后端 8080 无监听**，起始状态就是没起。
- 走通了命令行启动后端的路径：JDK 21 在 `D:\5E`（与 Node 24 混装）；
  6 个环境变量只配在 IDEA 的 Run Configuration 里（`.idea/workspace.xml`），
  命令行必须先 `eval` 出这些 env；`mvn` 要用 `mvn.cmd`（`mvn` sh 脚本在 Git Bash 下报
  `找不到主类 ClassWorldsLauncher`）。
- 发现 `spring-boot-maven-plugin` 配了 `<skip>true</skip>` → `spring-boot:run` 与
  `repackage` 全被跳过，`mvn spring-boot:run` 1.6 秒就 BUILD SUCCESS 且无应用日志。
  最终用 `dependency:build-classpath` + `java -cp` 手动启动成功。
- 用户 PowerShell 侧另有个坑：ExecutionPolicy 禁止 `.ps1`，敲 `npm` 会命中
  `D:\5E\npm.ps1` 报 UnauthorizedAccess，需 `Set-ExecutionPolicy -Scope CurrentUser
  RemoteSigned` 或改用 `npm.cmd`。

### 登录失败的真正原因（重点）
启动后端后实测 `POST /check/login`（cc/123456，账号在库里确实存在）返回
`{"msg":"请先登录"}` 且 **HTTP 500**。加 `-i` 看响应头才发现状态码是 500，
顺着日志挖到真实异常：`Invalid bound statement (not found): UserMapper.selectOne`。

**根因**：pom 同时引入 `mybatis-spring-boot-starter:3.0.3` 与
`mybatis-plus-boot-starter:3.4.0`。后者只适配 Boot 2，靠 `spring.factories` 注册自动配置，
而 Boot 3 已不再读取该文件 → MP 自动配置整体失效 → 容器里是原生 MyBatis 的
`SqlSessionFactory` → `BaseMapper` 的通用方法没有任何 SQL 绑定 → 所有 DB 操作 500。

**为什么现象是「请先登录」**：`loginconfign` 放行名单缺 `/error`，异常 forward 到 `/error`
后又被 `loginintercepter` 拦下，写回 `{"msg":"请先登录"}`。真实错误被完全掩盖 ——
这是本次排查绕弯最多的地方，**以后遇到「请先登录」但账号密码没问题，先查后端日志**。

### 定位手法（可复用）
1. `netstat -ano | grep LISTENING` 确认后端是否真的在监听；
2. `curl -i` 看**状态码**，别只看 body；
3. 用 `grep "请先登录"` 反查是哪段代码写的响应；
4. `javap -v xxx.class | grep String` 反编译目标 class，确认「源码改了但没编译」的可能性；
5. `mvn dependency:tree -Dincludes=...` 一次性看清依赖冲突。
前 4 步都排除了嫌疑后才挖到日志里的 `BindingException`，前面差点被
「excludePathPatterns 失效」的假象带偏（其实是 `/error` 被拦，不是放行名单失效）。

- 后端代码一行没改（用户明确要求）。修复需动 pom（换

### 三个「被掩盖的第二层缺陷」
1. **编译期缺 `-parameters`**：`register`/`sendcode` 这类散装参数接口全部 500
   （`Name for argument ... not available via reflection`）。
   项目用 `dependencyManagement` 引入 BOM 而非继承 `spring-boot-starter-parent`，
   自己声明的 compiler plugin 又漏了这个标志。**关键教训**：只改 pom 不改源码时
   Maven 会 `Nothing to compile` 跳过重编译，**必须 `mvn clean package` 才生效**——
   我因为这点白跑了一轮。
2. **`aitask.taskNo` 列名是驼峰**：`/admin/readai` 报 `Unknown column 'task_no'`。
   该库命名混用（`order.spu_id` 下划线、`aitask.taskNo` 驼峰），所以不能全局关掉
   下划线映射，只能加 `@TableField` 显式指定。
3. **`user` 表 AUTO_INCREMENT 计数器陈旧**：`/check/register` 报
   `Duplicate entry '1' for key 'PRIMARY'`。MP 对 `int` 主键不生成雪花 ID（id 保持 0），
   MySQL 把 0 解释成「取下一个自增值」→ 撞已有主键。直接 SQL 插 `VALUES (0,...)` 可复现。

## 又晚些：讨论「readspu 该不该放进用户侧 controller」

用户问：把 `readspu` 挪到 `controller.java` 让用户和管理员都能访问，是否更合理。
通读 `admincontroller` / `controller` / `usercontroller` / 两个拦截器 / `TokenSpu` 后给出结论：

- **方向对，但落点不对**。`controller.java` 是 `@RequestMapping("/check")` 的**认证域**
  （login/register/sign/logout/sendcode），套餐查询塞进去会混淆职责。
  正解是新建 `spucontroller`（`/spu/list`），保留管理侧 `/admin/readspu`。
- **更关键的语义缺陷**：`readspu()` 是 `spuMapper.selectList(null)`，**返回全部套餐，
  含 `status=0`（下架）的**；过滤是前端 `Home.vue` 自己做的 `status===1`。
  所以这个接口本来就不适合直接开放给普通用户——搬出去也只是把下架套餐暴露出去。
  用户侧与管理侧本就该是两个视图（只上架 / 含下架），不能共用一个方法。
- **不建议用 `excludePathPatterns("/admin/readspu")` 开口子**：`adminconfign` 拦
  `/admin/**` 形成的「命名空间 = 权限」约定很有价值，开例外会让后来人每次都要
  重新判断`/admin/*`是否例外。
- **待定决策**：`/spu/list` 要不要登录才能看。`loginintercepter` 拦 `/**`，新路径
  默认要登录；首页套餐列表通常应公开，若要公开需把 `/spu/**` 加进放行名单。
- **新发现的潜在缺陷（未修）**：`adminintercepter.preHandle` 里
  `usermapper.selectOne(queryWrapper).getRole()` 没有 null 判断。session 中的用户名
  在库里查不到时（典型场景：用户走 `/user/profile` 改了用户名，session 仍是旧值，
  见 MEMORY.md 的坑 8）会 NPE → 500。`/error` 现在已放行，会直接暴露成 500。

## 更深：定位「签到要登录 / AI创作有问题」（只改前端，后端待批）

用户报两个现象：① 签到领算力领不了、提示要先登录；② AI 创作界面有问题。
约束：**后端改动必须先问用户，前端可自行改**。

### 实测（后端 8080 与前端 5173 都在跑）
- 库里的账号是 **`ccc`(user) / `cyr`(admin)**，不是 `cc`；密码都是 `123456`。
- `POST /check/login` ccc → 成功；`GET /user/profile` → 正常返回 ccc 的数据
  ⇒ **登录与 session 完全正常**。
- `POST /check/sign` → **HTTP 500**，body 是 Spring 默认错误结构：
  `{"timestamp","status":500,"error":"Internal Server Error",
   "trace":"RedisConnectionFailureException: Unable to connect to Redis ..."}`。
- `POST /ai/poem`（ccc 算力 0）→ `{"code":500,"msg":"余额不足"}`（正常业务逻辑）。
- `GET /ai/show/list?sortid=1` → `data:[]`；`GET /admin/readai`（非管理员）→ 空响应体。

### 根因（两个现象是同一条因果链）
1. **Redis 在虚拟机 `192.168.246.132` 上，虚拟机没开** → 签到读不写不了 Redis → 500。
   （签到状态 key = username 存在 Redis 里，见 `controller.sign`。）
2. **前端把 500 伪装成了「请先登录」**：`api.js` 原来把「没有 code 字段的 JSON」
   一律当未登录，而 Spring 的 `/error` 响应体**恰好也没有 code 字段**
   → `RedisConnectionFailureException` 在界面上显示成「请先登录」。**这是本次的真正 bug。**
3. 因为签不到算力 → 算力 0 → `/ai/poem` 报「余额不足」→ 看起来像「AI 创作界面坏了」。

### 关键教训（以后别再踩）
> 前端看到「请先登录」**不等于**用户没登录。
> 后端 `/error` 的响应体也没有 `code` 字段，与拦截器的 `{"msg":"请先登录"}` 长得像、
> 语义相反。判断依据必须是 **HTTP 状态码 + 是否含 `status`/`error` 字段**，
> 不能只看「有没有 code」。
